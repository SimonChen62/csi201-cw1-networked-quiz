## 2. B-01 合法题库自检

```text
$ python -m server_modules.question_bank questions.json
network-basics: 5 questions
```

两套题库各 5 题，全部字段通过校验后才会被计数打印。

## 3. B-02 正式启动命令

```text
$ python server.py --host 127.0.0.1 --port 5067 --questions questions.json
SERVER_READY 127.0.0.1 5067
```

`SERVER_READY` 在 `server.py` 里只在**题库加载成功且 socket 绑定成功**之后打印，因此这一行同时证明两件事：校验通过、监听已建立。采集完成后进程被手动停止（正式运行时由 Ctrl+C 结束）。

原始输出见同目录 `2026-11-14-B-startup.txt`。

## 4. B-03 非法题库被拒且带定位

构造方式：复制 `questions.json`，把 `quizzes[0].questions[3].points` 改成 `5000`（合法范围是 1–1000）。

```text
$ python -m server_modules.question_bank invalid_bank.json
question bank rejected: ...\invalid_bank.json: quizzes[0].questions[3]: points must be 1-1000, got 5000
exit code 1
```

错误信息给出**文件 → 第几套测验 → 第几题 → 哪个字段 → 期望范围 → 实际值**，不需要人工逐行排查。文件被拒后进程以非零码退出，没有进入监听状态。

## 6. 本记录明确不覆盖的部分

这三点必须写清，否则容易被当成"已经做完"：

1. **未在官方镜像内复跑**。Docker Desktop 未启动，本轮证据全部产生于宿主 Python 3.13.18。镜像内复跑是待办项，不能靠本机结果替代。
2. **`server.py:287` 尚未注入业务处理器**。`main()` 目前只把题库传给 `Server(...)`，没有传 `request_handler` 与 `on_disconnect`，所以 `SERVER_READY` 之后发 `hello` 会得到 `UNKNOWN_COMMAND`。本记录只证明"校验 + 监听"这一段，**不能**证明业务消息可用。业务链路的证据是 `test_lobby.py` 的 38 项，以及接线后的端到端记录。
3. **一局完整比赛尚未打通**。引擎当前仍发 v2 事件名（`game_started` / `question_open`），v3 要求 `question` / `question_result` / `leaderboard`，因此即使接线完成，真 CLI 也还看不到题目。该项归 C。
