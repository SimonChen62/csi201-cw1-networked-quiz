## 4. B-03 非法题库被拒且带定位

构造方式：复制 `questions.json`，把 `quizzes[0].questions[3].points` 改成 `5000`（合法范围是 1–1000）。

```text
$ python -m server_modules.question_bank invalid_bank.json
question bank rejected: ...\invalid_bank.json: quizzes[0].questions[3]: points must be 1-1000, got 5000
exit code 1
```

错误信息给出**文件 → 第几套测验 → 第几题 → 哪个字段 → 期望范围 → 实际值**，不需要人工逐行排查。文件被拒后进程以非零码退出，没有进入监听状态。

## 7. 模块契约（供 A 接线时核对）

| 情况 | 行为 |

## 8. 本轮整理（首次提交之后的改动）

| 改动 | 位置 | 原因 |
| --- | --- | --- |
| 删除未被调用的 `_require_text_field` 与 `_BadRequest` | `lobby.py` | 死代码；且 `handle_request` 的 `except Exception` 会把它们吞成 `INTERNAL_ERROR`，留着只会误导后续维护 |
| `quit` 在返回响应的同时释放身份与座位 | `lobby.py` | 原实现把清理完全交给 A 的断线回调；A 若不关闭连接，同一 `user_id` 重连会误收 `DUPLICATE_USER` |
| `min_players` 不再强制抬到 2 | `lobby.py` | 原 `max(2, ...)` 会覆盖调用者显式传入的 1，单机调试与窄范围测试无法使用 |
| `Question.options` 改为 `MappingProxyType` | `question_bank.py` | `frozen=True` 只冻结字段绑定，不冻结字典内容，"只读题库"的承诺原来没有真正兑现 |
| 补充注释说明两种长度口径 | `question_bank.py` | 任务书对 `title`/`description`/`text` 写的是 **visible characters**，而 `options` 写的是 **characters**，两条规则并存是按规格执行，不是笔误 |

**核对结论（已对照任务书 PDF 原文）**：`title` 1-100、`description` 0-300、`text` 1-500 三项都写作 "visible characters"，`options` 写作 "each value 1-200 characters"。因此可见字符计数与 `len()` 并存是**符合规格**的，不做统一。

## 9. 尚未解决、需要跨成员确认的一项

`lobby.py` 使用了 appendix 错误码表里没有的码：`NOT_AUTHENTICATED`、`UNKNOWN_COMMAND`、`ALREADY_STARTED`、`NOT_IN_ROOM`、`LATE_ANSWER`、`INVALID_CHOICE`、`INTERNAL_ERROR`。appendix 的示例码表只有 12 个（`INVALID_MESSAGE`、`INVALID_SESSION`、`DUPLICATE_USER`、`QUIZ_NOT_FOUND`、`ROOM_NOT_FOUND`、`ROOM_FULL`、`ALREADY_IN_ROOM`、`NOT_ROOM_HOST`、`PLAYERS_NOT_READY`、`QUESTION_CLOSED`、`DUPLICATE_ANSWER`、`INVALID_ANSWER`）。

其中四处可以一一对应：`NOT_AUTHENTICATED → INVALID_SESSION`、`UNKNOWN_COMMAND → INVALID_MESSAGE`、`NOT_ALL_READY → PLAYERS_NOT_READY`、`LATE_ANSWER → QUESTION_CLOSED`、`INVALID_CHOICE → INVALID_ANSWER`。

但改名会同时牵动 C 的引擎返回值、现有测试断言与报告 6.2 的码表，**属于全组决定，本轮未擅自修改**。若要改，需要三处同时动作并同步报告。
