## v2 接口差异：联调前必须处理

最新版分工计划已增加“冻结版 v2”。当前 main 客户端仍按较早的 D/E 约定运行，C 新分支按 v2 发事件。下表是代码核对结果；本次进度更新没有把这些差异标为已修复。

| 位置 | main 当前实现 | v2 / C 分支 | 影响与对接人 |
|---|---|---|---|
| 开始请求 | `start_game` | `start` | A/B/D/E 统一路由和 CLI 映射 |
| 成员请求 | `inspect_room` | `room_members` | B/D/E 同步 |
| 答题选项 | 请求字段 `answer` | `choice` | C/D/E 同步，否则 C 无法取得选项 |
| 房间响应 | 嵌套 `data.room`、`host_user_id` | 房间字段直接在 data、`host_id` | B/D/E 更新响应解析，创建房间还需取得成员视图 |
| 成员名字 | `name` | `display_name` | B/C/D/E 统一 |
| 房间事件 | `room_update` | `room_updated`，并有 player_joined/left | B/D/E 确定成员与房主更新方式 |
| 发题事件 | `question` / `question_index` | `question_open` / `index` | 当前客户端不能用 C 的消息更新正在作答的题目 |
| 结算事件 | `question_result` / `answer` | `question_closed` / `correct` | 当前客户端不能按 C 的消息展示结算 |
| 最终排名 | `leaderboard` | `game_finished` | D/E 需更新结束态和显示 |
| 服务端失败 | A 当前 `type:error` | v2 规定 `type:response, ok:false` | A 统一封装；D 当前已经能返回匹配的 response 失败，不能把所有失败误认为都不支持 |

v2 表尚未列出当前客户端必需的 `hello` 登录及 `quit` / 关闭通知约定；房间状态大小写、房主转移字段也应由 A/B/D 一并补齐。不要仅改三个事件名就宣布协议已经一致。
